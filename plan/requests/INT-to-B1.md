# INT-1 (integration) to B1 (DB)

Context: Render gives ONE database user (not a superuser). `scripts/render-predeploy.mjs` runs `db/bootstrap.sql` unchanged as that user, then `db/migrate.mjs` as `app_migrator`, then the synthetic seed (`apps/api/src/jobs/seed-synthetic.ts`). Verified on a local PostgreSQL 16 with a `NOSUPERUSER CREATEROLE CREATEDB` owner (`scripts/sim-render-db.sh`). No change in `db/` was needed to make it work. These items would remove workarounds.

1. **`search.norm(text)` is not executable by `app_core`.** The trigram/FTS indexes on `portal.diagnosis_terms` and `portal.diagnosis_synonyms` call it, so any INSERT by `app_core` (definer functions included) fails with 42501. Effect today: the vocabulary (`db/seeds/010_diagnosis_vocabulary.sql`) cannot be loaded without a superuser except through a coordinator session as `app_runtime`. Ask: `GRANT EXECUTE ON FUNCTION search.norm(text) TO app_core;` in a new migration (0011). The pre-deploy step tries `SET ROLE app_core` first and will start to work by itself.
2. **`db/seed.mjs` needs a superuser** (`SET SESSION AUTHORIZATION`, RLS bypass). It cannot run on Render. The API job does the same work as `app_migrator` + `SET ROLE app_core` and `app_runtime`. Ask: either make `db/seed.mjs` use that path, or mark it "local and CI only" in `db/README.md`.
3. **`db/bootstrap.sql` on a managed service.** It works as a non-superuser only when the caller is a member of `app_migrator` (for `ALTER DATABASE ... OWNER TO` and the `REVOKE ... FROM PUBLIC` that follows). The pre-deploy step grants that membership to the Render user for the duration of the script and revokes it after. It also re-grants `CONNECT` to the Render user (bootstrap revokes it from PUBLIC). Please keep these two facts in mind when changing the file; a note in its header would help.
4. **Passwords.** `bootstrap.sql` creates login roles without passwords. The pre-deploy step creates `app_migrator`, `app_runtime`, `app_readonly_bg` with passwords first (same attributes), so the `IF NOT EXISTS` blocks are no-ops. `app_audit_writer` stays without a password (nothing logs in as it today). Tell INT if a job should.
5. **`/readyz`** uses `portal.migration_level()` and passes when applied >= the level compiled into the API (>= so that old instances stay ready during a deploy). OK with you?
6. The API copy `apps/api/db-support/0010_api_support.sql` is deleted; `apps/api/scripts/test-db.sh` uses `db/migrations` only.
