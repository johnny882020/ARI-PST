# 09 Synthetic data generator spec (for A8 and PR previews)

Package: `packages/synthetic-data`. Config: `yaml/synthetic-generator.yaml`. Covers contract rule "synthetic data only", REQ-072 tests, GATE-PROD-DATA guard.

## Rules
1. **Deterministic.** `generate(seed, profile)` returns the same data for the same seed. Uses a seeded PRNG (for example `mulberry32`), never `Math.random()`.
2. **Obviously fake.** Centers: `Synthetic Center A..E` (he: `מרכז סינתטי א..ה`). Users: `Synthetic Clinician A`, email `*.invalid` (RFC 6761 reserved TLD), `example.invalid`. No real names, no realistic IDs. Free text in request forms uses a fixed lorem-style bank beginning with `SYNTHETIC:`.
3. **Marker and guards.** Every sample row has `is_synthetic=true`. Preview and staging refuse to start if any row has `is_synthetic=false`. Production may hold synthetic rows until GATE-PROD-DATA closes (contract pack section 1). The go-live script must delete all `is_synthetic=true` rows (and their requests and audit slice via a documented reset), and the generator refuses to run when the flag `GATE_PROD_DATA_CLOSED=true` is set in production.
4. **Valid by schema.** All rows pass the same validators as the importer (shared package).
5. **Controlled distribution** (so k-rule tests have known answers): the profile defines exact cell counts, not only probabilities.
6. **Outputs:** SQL seed (`seed.sql`), NDJSON per table, and importer CSV + XLSX files (clean and dirty). Plus `expected.json` with the oracle for facet counts after k-rule.

## Profiles
| Profile | Samples | Centers | Purpose |
|---|---|---|---|
| `tiny` | 40 | 2 | Unit and RLS tests. Test file `sql/tests/test_rls_k.sql` uses the same shape |
| `preview` | 600 | 3 | PR preview environments, demos |
| `load` | 50000 | 5 | k6 load, index checks (A9) |
| `kedge` | 120 | 3 | k-anonymity edge cases: cells of size 1, 4, 5, 6; one family that only rolls up at group level; one facet where complementary suppression triggers |
| `stale` | 300 | 3 | Staleness: rows at 0, 150, 175, 181, 400 days since `last_verified_at` |

## Data shapes
- Centers 3 default: A (large), B (medium), C (small, only 4 records, always suppressed alone).
- Diagnosis mix from the starter vocabulary. Weights per profile in YAML.
- Age bands and sex: independent weights. Timepoint: 70 / 20 / 10.
- Collection month: uniform 2015-01 .. 2025-12 (synthetic).
- Attached data: each flag independent with set probabilities.
- Ethics approvals: 1 to 3 per center, refs like `SYNTH-ETH-A-001`. 5 percent of samples have no link (for warnings). One approval expired.
- Users: one per role per center where scoped. A user with two incompatible roles must **fail** to create (negative test).
- Requests: states across the whole workflow, including one rejected, one needs_info, one delivered; votes meeting and not meeting N-of-M.
- Audit events: generated by running real API calls in the e2e seed, not inserted directly (keeps the hash chain valid).

## Dirty import files (A8 negative corpus)
Generator `makeImportFile(kind)` produces files with a known list of defects and an `expected-report.json` (row_no, rule):
| Kind | Defect | Expected rule |
|---|---|---|
| `unknown_column` | extra column `patient_name` (synthetic header only, empty values) | UNKNOWN_COLUMN |
| `id_like` | cell `123456789` (synthetic 9 digits) in a text cell | IDENTIFIER_SUSPECTED |
| `email_like` | `person@example.invalid` | IDENTIFIER_SUSPECTED |
| `full_date` | `2024-05-17` in `collection_month` | IDENTIFIER_SUSPECTED |
| `bad_enum` | `sex=X` | VOCAB |
| `bad_month` | `2024-13` | FORMAT |
| `dup_rows` | 5 identical rows | DUPLICATE_ROW |
| `wrong_center` | update with other center | CENTER_MISMATCH |
| `expired_ethics` | ref of expired approval | ETHICS_EXPIRED |
| `xlsx_formula` | `=1+1` cell | IMPORT_FILE_INVALID |
| `oversize` | 20001 rows | IMPORT_FILE_INVALID |
| `bom_csv`, `crlf_csv`, `he_headers_xlsx` | valid files in odd encodings | accepted |
Never use real-looking identifiers: the "ID like" value is a fixed obviously synthetic string documented in the generator.

## Test hooks (A8)
- Property tests (fast-check): for any generated dataset and any filter set, no external facet cell is below k; sum of shown buckets equals total when no suppression; adding one sample never changes a bucket by more than 1.
- Oracle: `expected.json` gives the facet output for profile `kedge`.
- RLS test: for each role and table, an allow-list matrix (see 03 access matrix) is asserted by trying SELECT under `SET ROLE`.
- Round trip: `tiny` -> export -> import -> equal checksums.
- Hebrew/English: labels exist for every vocabulary value (i18n coverage test).

## API
```ts
generate(opts: { seed: number; profile: 'tiny'|'preview'|'load'|'kedge'|'stale'; now?: string }): SyntheticDataset
toSql(ds): string;  toNdjson(ds): Record<string,string>;
makeImportFile(kind: DirtyKind, opts?): { bytes: Uint8Array; format: 'csv'|'xlsx'; expectedReport: ExpectedRow[] }
```
`now` is injected (ClockPort) so staleness tests are reproducible.
