# Code review REVIEW-1 (2026-11-14)

Scope: `apps/api`, `apps/web`, `packages/*`, `db/` (read only for `db/bootstrap.sql` and `db/migrate.mjs`), against `packages/contracts/openapi.yaml`, `CLAUDE.md` and `plan/11-integration/canonical-decisions.md`. Synthetic data only.
Method: reading the code, plus the package tests. Not done: a pen-test, DAST, a load test, a run on the Render demo.
Severity: **High** = a security control can be bypassed or data can leak; **Medium** = a control is weaker than the plan says, or a user flow breaks; **Low** = hardening, dead code, or a mismatch with no direct impact.

## What was checked and found sound
- CSRF: double submit plus session token, Origin and `Sec-Fetch-Site` checks on every unsafe `/api/` call; the only exemptions are the CSP report, client error report and public form endpoints (`apps/api/src/http/core.ts`).
- Cookies: `__Host-sid` HttpOnly, Secure, SameSite=Strict, path `/`, no Domain (test in `apps/api/test/auth.test.ts`). Sessions are random 256-bit tokens; only the SHA-256 is stored.
- Authorization: one table (`packages/domain` `OPERATION_ACCESS`) equals `x-roles` in the contract, tested for every role and every operation (`apps/api/test/authz-matrix.test.ts`).
- RLS: the API logs in as `app_runtime` and starts every transaction with `portal.begin_session`; the production start refuses an elevated login (`apps/api/src/server.ts`).
- k-anonymity output: external roles get no `k`, no threshold, and `null` counts for masked cells (`apps/api/test/requests.test.ts`).
- Problem details: fixed text per code, no values, no identifiers (`apps/api/src/http/problem.ts`). The unhandled-error log has the error class and code only.
- CSP: no `unsafe-eval`; zod 4 runs jitless (`apps/web/src/zod-config.ts`, imported first in `apps/web/src/main.tsx`). No `dangerouslySetInnerHTML` in `apps/web/src`.
- AES-256-GCM for TOTP secrets uses a 12-byte IV and a 16-byte tag and rejects malformed input.
